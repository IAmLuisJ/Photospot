Before anyone sees it 6 hard gates

Ordered by what blocks what. The first four are a single afternoon; the fifth is the one that actually decides whether the product works.

Gate 1 · Hosted database

  • Run npx supabase login

    Never run, so there is no hosted project. Everything below waits on it, and nothing in production can be verified until it exists.

    Blocking
  • Create the project and push all 14 migrations

    supabase db push. They replay clean from empty locally, which is the check that they will apply at all.

    Waiting
  • Set three environment variables on Vercel

    SUPABASE_URL, SUPABASE_ANON_KEY, and — easily missed — SUPABASE_SERVICE_ROLE_KEY. Voting and commenting need the third: spots.score is deliberately not writable by ordinary users, so the server refreshes it with the service role.

    Waiting
  • Verify sign-in against production

    Script it rather than clicking it. Two silent auth bugs in this project were only ever found by driving the magic-link flow end to end.

    Waiting

Gate 2 · Map tiles

  • Point MAP_STYLE_URL at a real provider

    It currently defaults to MapLibre's demo tiles, which are development-only. Protomaps or MapTiler — both bill flat rather than per map load, which is the right shape for a free product whose core interaction is panning around.

    Blocking

Gate 3 · Something worth looking at

  • Seed 30–50 Grand Rapids spots with real photographs

    The spec names this the dominant risk, and it is not a software risk. The map is worthless with twenty spots and useful with two hundred; someone who opens it and finds four pins does not come back. Six seeded spots exist today.

    Blocking

Worth doing before real users, not before launch

None of these stops a launch. Two are privacy or abuse questions that get worse with traffic, so they are worth doing while the traffic is still friends.

ItemWhy it mattersWeight
Ballot privacy signals.profile_id is readable by anyone, so who voted for what can be enumerated. Vote counts are meant to be public; the per-person ballot is not. Privacy
Report rate limiting One angry person can file fifty reports. The admin queue is what makes that visible, which is the prerequisite for knowing what limit to set. Abuse
Schedule refresh:hot The “what's happening now” ranking works and is tested, but nothing runs it, so hot scores never move. Ops
Sweep orphaned photos Photos upload before the spot exists, so an abandoned submission leaves files in storage that nothing ever collects. Ops
Replace a photo on an existing spot Editing covers text fields and gallery links only. A bad photo currently has to be lived with. Gap
Comment dates show UTC A comment posted at 8pm Eastern reads as tomorrow. The honest fix needs the viewer's timezone, which the server cannot know. Polish

Deliberately not built

Recorded so nobody re-opens them by accident. Each was a decision, not an omission.

Not builtReasoning
Sponsorships and ads The data model leaves the seam. The feature waits for traffic worth selling.
Server-side clustering The viewport query caps at 500 rows, which is fine until one view holds more than that. Designing it needs a real corpus.
An index on the filter columns Measured at 5,000 synthetic spots: the geographic index does the work, and a GIN index buys about 11% against a write cost on every vote.
Pre-publish review queue A queue only the author can clear becomes a bottleneck the moment the product works. Spam risk at this scale is negligible.
Threaded comments, notifications, saved lists Explicitly out of MVP scope.
